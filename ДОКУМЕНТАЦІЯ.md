# Документація проєкту — чому саме такий стек

## Що це за проєкт

Домашнє завдання: зробити сайт, дотичний до обраної професії (поки що тільки головна сторінка), і прикріпити посилання в Classroom. Тема — автосервіс/СТО: зрозуміла сфера, на якій легко закрити всі пункти із завдання — назва, заголовок, пояснення терміна, послуги, європейське обладнання, графіка й таблиці.

## Стек

- **HTML5** — розмітка сторінки
- **CSS3**, чисті стилі без жодного фреймворку — весь вигляд сайту
- **Vanilla JavaScript**, без бібліотек — кілька невеликих інтерактивних деталей
- **GitHub** — репозиторій з кодом
- **Vercel** — хостинг готового сайту

## Чому без React/Vue і подібних фреймворків

Це одна статична сторінка без стану, без роутингу, без даних, які треба десь тримати й оновлювати. Фреймворк тут не додав би нічого корисного — тільки білд, node_modules і зайвий час запуску. HTML, CSS і JS відкриваються одразу, без жодної збірки. Для домашнього завдання це і простіше зробити, і простіше перевірити.

## Чому без Bootstrap/Tailwind

Хотілось, щоб сайт виглядав як власна робота, а не "ще один сайт на Bootstrap" з типовими кнопками й сіткою. Усі кольори, відступи, радіуси винесені в CSS-змінні (`:root`), тому стиль витриманий по всьому сайту і міняється в одному місці. Та й файл стилів виходить легшим — у ньому немає нічого зайвого, тільки те, що реально використовується.

## Чому дизайн саме такий

Темна тема з одним яскравим акцентним кольором (помаранчевий) — поширений і доречний прийом для автотематики: асоціюється з інструментом, енергією, не зливається з типовими "блакитно-білими" корпоративними сайтами. Шрифт Manrope — сучасний, геометричний, добре читається і в заголовках, і в тексті, тому не знадобився другий шрифт.

## Чому саме такий поділ файлів

`index.html`, `styles.css`, `script.js` — три окремі файли замість одного великого. Розмітка, стилі й логіка не змішуються між собою, і завжди зрозуміло, де що шукати.

## Навіщо JavaScript, якщо сайт статичний

Бекенда й бази даних тут немає — усе вміщається на одній сторінці. JS відповідає тільки за дрібні речі, які роблять сторінку живою: мобільне меню, плавну появу блоків при скролі, анімовані цифри в статистиці та умовну відправку форми заявки (реального сервера для прийому заявок у домашньому завданні немає, тому форма просто показує підтвердження).

## Чому іконки — SVG, намальовані вручну

Усі значки (шина, гайковий ключ, манометр тощо) — це inline SVG, а не картинки з інтернету. Сторінка не чекає на завантаження зображень, іконки однаково чіткі на будь-якому екрані й не залежать від сторонніх сайтів, які можуть зникнути або повільно віддавати файли.

## Чому GitHub

Код має десь лежати, щоб його можна було переглянути і щоб із нього сам підтягував сайт Vercel. GitHub — стандартний і безкоштовний варіант, а посилання на репозиторій зручно прикріпити в Classroom поруч із живим сайтом.

## Чому Vercel

Vercel бере репозиторій із GitHub і сам публікує сайт без жодних налаштувань — це ж звичайний статичний HTML. Кожен новий пуш у GitHub автоматично оновлює вже опубліковану сторінку, тому посилання для Classroom не змінюється з часом.
